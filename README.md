The focus is live inspection: train or load a model, open the UI, adjust inputs and epochs, and immediately see what the network produces internally and externally.

## Main features

- **Live generator visualization**: randomize or control the latent input and see generated image outputs update.
- **Live discriminator visualization**: feed generated images through the discriminator and inspect its response.
- **Layer-by-layer inspection**: choose network layers and visualize intermediate activations rather than only final outputs.
- **Epoch navigation**: move between saved generator and discriminator checkpoints to watch the model evolve during training.
- **Training statistics**: save losses and discriminator scores during training for later plotting and comparison.
- **Post-training asset pipeline**: export TensorFlow Lite models, produce sample and reproduction images, and build training-comparison plots.
- **Multiple interfaces**: a Vue web UI is the default interface, with a legacy Tkinter UI still available through configuration.
- **Android model path**: trained models can be converted toward TensorFlow Lite usage for the included Android app experiment.
- **From-scratch model recreation**: the `create_from_scratch/` workspace exports a saved Keras generator into JSON artifacts and replays it with Keras, pure Python, C, C++, and Rust implementations for layer-by-layer comparison.

## Repository layout

```text
.
├── model_creator/          # GAN model definitions, training scripts, Flask visualization API, plotting utilities
├── web-ui/                 # Vue/Vite frontend for live model visualization
├── android_app/            # Android experiment for applying exported models
├── create_from_scratch/    # Experimental Keras, no-Keras, C, C++, and Rust generator recreation workspace

```

Important entry points:

- `model_creator/train_model.py` trains the GAN, saves generator/discriminator checkpoints, and writes statistics.
- `model_creator/produce_assets.py` runs the post-training asset pipeline: TensorFlow Lite exports, generated sample sets, reproduction-search images, and comparison plots.
- `model_creator/run_ui_server.py` starts the Python visualization backend.
- `model_creator/ganalyzer/GUIWebPage.py` exposes the Flask API used by the web UI.
- `web-ui/src/App.vue` mounts the generator input panel plus generator and discriminator visualization panels.
- `web-ui/src/js/webUI.ts` coordinates frontend state, API calls, selected epochs, and layer visualization updates.
- `create_from_scratch/0_prepare_model.py` extracts a `.keras` generator checkpoint into JSON model configuration, metadata, and weights for non-Keras runtimes.
- `create_from_scratch/6_display_dimension_and_difference.py` compares the intermediate layer outputs generated by the Keras, pure-Python, C, C++, and Rust recreations.

## How the live visualization works

1. The training script saves generator and discriminator models at regular epoch intervals.
2. The Flask backend loads the available checkpoints for the configured model name and latent-space size.
3. The Vue frontend synchronizes with the backend and receives the available layer lists and checkpoint count.
4. When you move sliders or choose a layer, the frontend sends the current input, target model, layer name, and epoch selection to the backend.
5. The backend runs the selected model up to that layer and returns the activation values.
6. The frontend renders those values as images or grids so you can watch the network change live.


## From-scratch recreation workspace

The `create_from_scratch/` directory is an experimental validation workspace for replaying a trained generator without relying on TensorFlow/Keras at inference time. It uses one saved `.keras` generator as the reference, extracts its architecture and weights, then runs the same fixed latent vector through several implementations:

```text
create_from_scratch/
├── config.toml                             # Shared paths for the selected source model and comparison outputs
├── 0_prepare_model.py                      # Extracts config.json, metadata.json, and model.weights.json from a .keras model
├── 0_models/                               # Source .keras checkpoints and extracted JSON artifacts
├── 1_implementation_keras/                 # Reference Keras execution and intermediary layer dumps
├── 2_implementation_without_keras/         # Pure-Python implementation of supported layer operations
├── 3_implementation_c/                     # C implementation of supported layer operations
├── 4_implementation_cpp/                   # C++ implementation using nlohmann/json for JSON artifacts
├── 5_implementation_rust/main/             # Rust implementation using serde_json
└── 6_display_dimension_and_difference.py   # Shape and numeric-difference comparison utility
```

Typical workflow:

1. Train or copy a generator checkpoint so `create_from_scratch/config.toml` can point `keras_file_path` at the desired `.keras` file. The default path is under `create_from_scratch/0_models/keras_models/<model_name>/generator_epoch_001000.keras`.
2. From `create_from_scratch/`, extract the model into JSON artifacts:

   ```bash
   python 0_prepare_model.py
   ```

   This creates `0_models/json_models/<model_name>/config.json`, `metadata.json`, and `model.weights.json`.

3. From `create_from_scratch/`, run the reference Keras implementation to save layer outputs and a generated image under `1_implementation_keras/intermediary/`:

   ```bash
   python 1_implementation_keras/main.py
   ```

4. From `create_from_scratch/`, run one or more recreated implementations. Each implementation writes its own configured `intermediary/` layer dumps using the same fixed latent vector:

   ```bash
   python 2_implementation_without_keras/main.py

   cc 3_implementation_c/main.c -o 3_implementation_c/main && ./3_implementation_c/main

   g++ -std=c++17 4_implementation_cpp/main.cpp -o 4_implementation_cpp/main && ./4_implementation_cpp/main

   cargo run --manifest-path 5_implementation_rust/main/Cargo.toml
   ```

5. From `create_from_scratch/`, compare output shapes and numerical differences against the Keras reference:

   ```bash
   python 6_display_dimension_and_difference.py
   ```

The comparison utility expects the intermediary directories configured in `create_from_scratch/config.toml` to exist. The C, C++, and Rust versions currently write `out.ppm`, while the Python implementations write `out.jpg`; all implementations write text dumps for the layer-by-layer numeric comparisons.

## Quick start

### 1. Configure the model and dataset

Edit `model_creator/config.py` to choose the dataset, latent-space size, output size, checkpoint interval, and UI mode.

The current defaults expect image data under a path similar to:

```text
model_creator/datasets/<dataset_name>/<image_size>/
```

The project currently targets RGB image generation, with model configuration centralized in `model_creator/ganalyzer/model_config.py` and `model_creator/config.py`.

### 2. Train or resume a model

From `model_creator/`, run:

```bash
python train_model.py
```
